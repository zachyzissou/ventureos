## Control4 + HomeKit State Mismatch — Research

### Problem
- Control4 media zones report `idle` when powered off (not `off` or `standby`)
- HomeKit's `MEDIA_PLAYER_OFF_STATES` = (`off`, `unknown`, `standby`, `None`) — does NOT include `idle`
- Result: Home app shows TVs as "on" when they're actually off

### Root Cause (Source Code Confirmed)
- `control4/media_player.py` line ~200: `return MediaPlayerState.IDLE` when `POWER_STATE` is false
- This is hardcoded — no configuration option to change it
- Also: `TURN_ON` not in `supported_features` (only `TURN_OFF` + `SELECT_SOURCE`)
- `media_player.turn_on` returns 500 error — must use `select_source` to power on

### HomeKit State Mapping (from `homekit/type_media_players.py`)
```python
MEDIA_PLAYER_OFF_STATES = (STATE_OFF, STATE_UNKNOWN, STATE_STANDBY, "None")
hk_state = 1 if current_state not in MEDIA_PLAYER_OFF_STATES else 0
```

### Fix: Universal Media Player Wrapper (Not Yet Implemented)
- Standard community solution for integrations that don't report `off` correctly
- Wraps Control4 entity, passes through all commands
- Maps `idle` (no source) → `off` for HomeKit
- Can add `turn_on` support (by calling `select_source`)
- One YAML block per TV in `configuration.yaml`
- Original C4 entities get hidden from HomeKit; wrapper gets exposed instead
- **User approved concept, not yet implemented**
